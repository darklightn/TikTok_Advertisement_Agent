# 直写版数据映射｜S-20260908-C1

机器规则唯一来源为 `config/sync.yaml` 中的 `schema_registry`。本文件解释执行规则，不提供另一套类型推断器。当前注册表含 45 个固定结构变体、1007 个源字段定义、5 个明确授权的数值辅助字段。

## 固定匹配

按店铺相对路径的目录、必要时的文件主名、扩展名过滤候选，再按候选规定的表头行读取并严格比对全部源字段名称和顺序。变体不是按店铺名、日期或单元格值选择。同目录的 58/66 列订单、单日/区间达人明细、products/skus 和 summary/items 是预先登记的不同结构；不能合并、补列或临时重新推断。

表头单元格的两端空白不构成业务名称；多层名称用全角冒号连接。普通业务 Text 值不做这种处理。固定 `data_start_row` 之前的说明行不算业务记录；之后保留至少有一个源字段非空的记录。0、False、空格/制表符文本非空；只有 null/真空单元格/空字符串为空。CSV 的行号是逻辑记录序号。

## 类型和值

- Text：文本原样，包括前导 0、尾部制表符、JSON 字符串、电话、状态、编码和说明。原为数值的标识字段用原始 XML 数值精确展开；明确的全零编号格式（如 `00000`）保留补零含义。不经 float。
- Number：Python `Decimal`；保留完整底层数值，不按显示小数位裁掉数据。它是本地精确数值对象，不是“把数字降成文本”。阶段 09 必须将其序列化为 API 的 JSON 数值，不能加引号。超过安全整数上界的整数型业务值报错；标识字段应当早已固定 Text。
- DateTime：输出 UTC Unix 毫秒整数。没有时区的业务日期/时间按 Asia/Manila（本项目 UTC+08:00）；有 Z/偏移量的输入保留它所表达的同一时刻。XLSX 数值按工作簿 1900/1904 日期系统解释；1900 序列日 60 拒绝。只支持明确的 ISO、样本中美式月/日/年时间格式以及 XLSX 日期序列，不猜任意日期格式。
- Boolean：输出真正的 bool 或 null，不用字符串真假值，也不把 False 当空值。原生布尔和明确 true/false/1/0 可解析；不使用 Python 对非空字符串的默认真假判断。

结构化 Number/DateTime/Boolean 解析可去除两端空白；清除后为空则为空。Number/DateTime 的 `-`、`--` 按已批准规则转 null，绝不转 0。其他非法字符、NaN/Infinity 不自动当空。Text 中的这些内容保留。

## 百分比

明确带 `%` 的文本只除以 100 一次；XLSX 百分比格式的底层数值直接保留。普通裸值的尺度来自固定字段的 `bare_percent_unit`，不按值大小猜。

`0.0396756` + `0.00%` 的显示目标是 3.97%；底层仍为 `Decimal('0.0396756')`。`0.396756` 不是 3.97%，不为迎合显示而多除一次。

注册表将计划表现中的裸 `ctr` 明确登记为 points：该来源给出 `3.50`，对应比例 0.035。此规则只作用于这个预先登记字段，不外推到其他裸小数。其余登记为 ratio 的裸值直接保留。固定样式有 0.00% 时沿用；文本百分比的统一目标模式在注册表中明确为 0.00%。

## 金额与币种

金额解析成 Decimal。逗号只能按合法千位分隔处理，不随便删掉所有逗号。字段声明的币种来源是工作簿 Currency 元数据或已有币种列；不能按店铺名猜 PHP，也不能将广告 USD 与店铺 PHP 混用。

需要符号解析的金额必须与已知币种一致。同一币种源列出现多个代码，或符号/元数据互相冲突，报告 CURRENCY_MISMATCH；有实际金额却没有必要币种证据，报告 CURRENCY_MISSING。整列金额为空、币种亦为空时允许先输出 currency=null，不伪造单位。已有币种源列继续原样保留，不新增币种字段、不换算金额。

范围文本 `>60`、“已付款”等不是可精确数值化的金额/数量，不按名称硬转数字。它们已在对应 Schema 中明确登记 Text。源履约快照的裸当前值保持其原始 Number 和已有单位列，不套用清洗后报表的比例规则。

## 不改变的边界

单个 XLSX 只支持一个 Worksheet；错误 dimension 不能截断实际单元格。公式只使用已保存的可靠缓存；缺缓存或 Excel 错误值报告错误，不算公式、不连接 Excel。

row_key 只用于本地记录定位，不输出到 target_fields。阶段 08 不提供远程表名、不做表名缩短、不读写 state、不创建表、不清空记录。超长名称“首＋完整日期/日期范围＋尾＋8位hash”由后续 planner 阶段落实。
