# 清洗字段来源关联与处理规则

## 一、统一清洗规则

1. 所有 ID 统一按文本保存，去除首尾空白和制表符，不能转科学计数法、不能丢精度。
2. 所有金额统一保存为纯数值，币种单独使用币种字段，不保留“₱22,371.37”这类带符号字符串。
3. CTR、CTOR、加购率、退款率、毛利率、视频播放率等比例类指标，底层统一保存为 0—1 小数并显示为百分比；ROI / ROAS 保持倍率，不转换为百分比。
4. 不同原始字段的百分比表达方式必须按“原始数据源 + 原始字段”建立固定转换规则，不能仅根据数值大小判断是否除以100。
5. 空值与0严格区分：没有指标、不适用、无法确定时保留空值；真实发生值为0时保留0。
6. 所有区间型清洗表必须写入统计开始日期和统计结束日期；所有快照型清洗表必须写入实际采集日期或快照日期。
7. 所有比率、单价、均值、CPC、CPM、CPO、ROI、CTOR等衍生指标，在跨行、跨日、跨对象汇总时，必须先汇总基础分子和分母再重新计算，禁止直接平均已有结果；无法取得基础量时优先使用平台对应统计粒度的官方值，仍无法取得时留空。
8. 订单经营明细以“订单 × SKU行”为粒度。同一 Order ID 存在多个 SKU 行时，SKU级字段按SKU行正常统计；订单级金额、优惠、运费等字段在汇总时按 Order ID 去重，同一订单只计算一次。
9. `-`、`N/A`、`NaN`文本、空字符串及明确不适用值按字段语义转为空值，不通用转换为0。
10. JSON路径使用点号表示，数组使用 `[]`；存在报表说明行或多级表头时按表头锚点定位真实表头，不依赖固定行号。
11. 商品分析表现的重复字段必须结合上层分组生成唯一字段名，例如 `全部.GMV`、`全部.商品点击量`；商品名、商品ID、GMV区间、发品状态保持原字段名。
12. 清洗表之间不互相作为数据源；每张清洗表只读取已经固定的原始导出表、运行参数/上下文及必要人工录入数据。
13. 区间型原始报表只读取与本次清洗 `start_date + end_date` 完全匹配的文件，不拼接其他包含、被包含或部分重叠的区间文件；精确区间文件不存在时报告缺少原始数据。
14. `GMV Max 计划小时表现`为区间文件选择的例外：按计划 × 日期逐日读取目标日期范围内已经导出的全部日文件并合并。
15. `GMV Max 建议快照`当前只读取 `items` 文件：同一计划选择最新的 `计划名称__items__采集日期.xlsx`。`summary` 文件当前不参与清洗。缺少 `items` 文件时按缺少原始数据处理并阻断本次计划诊断；`items` 文件存在但没有 ROI 建议时，不阻断计划诊断。
16. 人工成本表中，成本字段留空表示“未知”；真实没有该项成本必须明确填写 `0`。任一必需成本项为空时，单位基础成本及其派生毛利率、保本ROI留空。
17. 所有自行计算的除法类指标统一遵守：分母为0或空时结果留空；分母>0且分子为0时结果为0。不得产生除零错误。
18. `退货退款明细`关联订单历史时，搜索当前店铺 `店铺数据/订单明细/` 下已经存在的全部历史订单文件；同一 Order ID 在多个文件中金额一致则视为同一订单，金额冲突则订单实付留空并记录冲突，完全找不到则订单实付留空。

| GMV Max总收入 | 广告户数据/GMV Max 计划总览 | Gross revenue (Current shop) | — | 读取总计行；若无总计行则汇总明细行。金额转数值。 |
| 实际ROI | 计算字段 | GMV Max总收入、广告总成本 | — | GMV Max总收入 ÷ 广告总成本；成本为0时留空，不平均原始 ROI。 |
| 广告币种 | 广告户数据/GMV Max 计划总览 | 币种 | — | 去重后应为单一币种；直接写入 ISO 币种代码。 |
