# 清洗表 Upsert 唯一键与写入规则

## 一、适用范围

本文档只负责规定 16 张清洗表的：

- Upsert 唯一键
- 唯一键标准化方式
- 新增 / 替换规则
- 计划 ID 缺失时的计划名称回退规则
- 无法生成唯一键时的处理方式
- 最新状态表的时间保护规则
- 清洗文件安全写入规则

字段来源、字段处理、表头、原始依赖继续以已经冻结的另外三份文档为准，不在本文档重复定义。

---

## 二、统一 Upsert 规则

### 1. 唯一键作用范围

当前清洗结果按店铺分别写入：

```
店铺名/20_清洗数据/
```

因此本文档中的唯一键均在“当前店铺对应的单张清洗表”范围内生效。

`店铺ID`继续作为清洗字段保留并进行店铺一致性校验，但不重复加入每一张表的 Upsert 唯一键。

如果未来改为跨店铺统一数据库存储，再在所有唯一键前统一增加`店铺ID`。

### 2. Upsert 基本行为

对本次新生成的每一行：

- 唯一键在目标清洗表中不存在 → 新增。
- 唯一键在目标清洗表中已存在且只存在 1 行 → 默认使用本次新生成的完整行整体替换旧行。
- `退货退款明细`、`店铺健康明细`、`履约表现明细`按照本文档规定的时间保护规则决定替换、跳过或报冲突，不直接执行普通整行替换。
- 不做“旧值非空就保留”的字段级拼接；计划ID回退场景中“不得用空计划ID覆盖已有非空计划ID”是唯一明确例外。
- 同一个唯一键在现有清洗表中已经存在多行 → 视为历史重复键异常，停止该目标表写入并报告重复键。
- 本次清洗结果自身出现无法按特殊规则消解的重复唯一键 → 停止该目标表写入并报告重复键，不自行任选一行。

### 3. 唯一键字段标准化

参与唯一键的字段在比较前必须先标准化：

- ID：按文本处理，去除首尾空白和制表符。
- 日期：统一为 `YYYY-MM-DD`。
- 小时：统一为同一种小时表达，例如 `00:00`—`23:00`。
- 计划名称回退键：去除首尾空白；不做模糊匹配。
- `Post ID`、`SKU ID`、`订单ID`、`售后单号`、`变更ID`等不能转为数值。

文档中的 `+` 只表示“多个字段共同组成复合唯一键”，不表示程序直接拼接字符串。

程序内部应使用有序字段元组等结构保存复合键，例如：

```
(计划ID, 商品ID, Post ID, 统计开始日期, 统计结束日期)
```

禁止把多个字段直接无分隔拼接成一个字符串作为唯一键。

### 4. 唯一键必要字段为空

除本文档明确规定的计划名称回退规则外，唯一键中的必要字段为空时：

- 该行不得写入目标清洗表。
- 记录“无法生成 Upsert 唯一键”错误。
- 不使用模糊匹配、行号、Excel 行位置或随机值代替。

## 三、计划标识规则

以下表涉及计划标识：

- 计划诊断
- 素材诊断
- 计划小时表现
- 计划配置历史
- 计划变更记录

统一规则：

1. `计划ID`非空 → 唯一键中的计划标识使用`计划ID`。
2. `计划ID`确实无法取得 → 使用`计划名称`作为回退标识。
3. 当前业务前提：同一店铺内计划名称唯一，不会出现同名计划。
4. 计划名称只作为计划ID缺失时的兜底，不新增任何“计划身份键”输出字段。

### 计划ID回退的最小防重复规则

当本次新行有`计划ID`时：

- 先按`计划ID + 该表其他唯一键字段`查找旧行。
- 若未命中，再允许查找“旧行计划ID为空 + 计划名称完全一致 + 其他唯一键字段完全一致”的旧行。
- 唯一命中时，用本次新行替换旧行并补入计划ID。
- 命中多行时停止写入并报重复键/身份冲突。

当本次新行没有`计划ID`时：

- 按`计划名称 + 该表其他唯一键字段`匹配。
- 若唯一命中的旧行已经存在非空计划ID，更新该行时必须保留旧计划ID，不得用空值覆盖。
- 若匹配到多行，停止写入并报重复键/身份冲突。
- 若没有匹配行，则允许按计划名称回退键新增。

## 四、16 张清洗表 Upsert 唯一键

| 序号 | 清洗表 | Upsert 唯一键 | 说明 |
|---|---|---|---|
| 1 | 广告户诊断.xlsx | `广告户ID + 统计开始日期 + 统计结束日期` | 同一广告户、同一统计区间只保留一行。 |
| 2 | 计划诊断.xlsx | `计划ID + 统计开始日期 + 统计结束日期`；计划ID缺失时用`计划名称 + 统计开始日期 + 统计结束日期` | 计划ID为主，计划名称仅兜底。 |
| 3 | 素材诊断.xlsx | Video：`计划ID + 商品ID + Post ID + 统计开始日期 + 统计结束日期`；Product card：`计划ID + 商品ID + 素材类型 + 统计开始日期 + 统计结束日期`；计划ID缺失时对应位置使用计划名称 | 与已冻结的素材内部关系一致。Product card 的 Post ID 仍为空。商品ID经过既定回退规则后仍为空时，该行不能安全生成唯一键，不写入并报错。 |
| 4 | 商品经营诊断.xlsx | `商品ID + 统计开始日期 + 统计结束日期` | 一个商品在一个统计区间只保留一行。 |
| 5 | 店铺诊断.xlsx | `统计开始日期 + 统计结束日期` | 当前文件已经按店铺物理隔离，因此一个店铺在一个统计区间只应有一行。 |
| 6 | 广告户状态快照.xlsx | `广告户ID + 采集日期` | 同一广告户每天保留一个状态快照；同日重新清洗时替换。 |
| 7 | 计划小时表现.xlsx | `计划ID + 日期 + 小时`；计划ID缺失时用`计划名称 + 日期 + 小时` | 一个计划在某一天某一小时只保留一行。 |
| 8 | 计划配置历史.xlsx | `计划ID + 采集日期`；计划ID缺失时用`计划名称 + 采集日期` | 当前原始配置按计划×采集日保存；同日重新采集/清洗时替换当日配置。 |
| 9 | 计划变更记录.xlsx | `计划ID + 变更ID`；计划ID缺失时用`计划名称 + 变更ID` | 同一变更可能重复出现在不同区间导出文件中，按变更ID识别。变更ID最终仍为空时不写入并报错。 |
| 10 | SKU状态库存明细.xlsx | `SKU ID + 快照日期` | 一个SKU在一个共同快照日期只保留一行。 |
| 11 | 订单经营明细.xlsx | `订单ID + SKU ID` | 与已冻结的“订单 × SKU行”粒度一致；同一订单同一SKU后续重新出现时更新该事实行，不按导出区间重复保留。 |
| 12 | 退货退款明细.xlsx | `售后单号` | 按售后单实体保存最新状态，写入时必须比较采集时间。 |
| 13 | 商品评价明细.xlsx | `订单ID + 商品ID + SKU ID` | 当前原始数据没有评价ID，以订单、商品、SKU共同识别一条评价。 |
| 14 | 营销活动明细.xlsx | `营销活动ID + 统计开始日期 + 统计结束日期` | 同一营销活动在不同统计区间的GMV、订单、折扣和ROI属于不同统计结果，必须保留区间。 |
| 15 | 店铺健康明细.xlsx | `采集日期 + 类别 + 指标` | `采集日期`由`采集时间`取日期部分，仅作为内部Upsert键使用；同日同指标保留采集时间最新的一条。 |
| 16 | 履约表现明细.xlsx | `采集日期 + 类别 + 指标` | `采集日期`由`采集时间`取日期部分，仅作为内部Upsert键使用；同日同指标保留采集时间最新的一条。 |

## 五、各表特殊说明

### 1. 素材诊断

#### Video

唯一键：

```
计划ID + 商品ID + Post ID + 统计开始日期 + 统计结束日期
```

计划ID确实缺失时，对应位置使用计划名称。

其中：

- `Post ID`必须存在。
- `商品ID`优先读取素材源中的`product_id`。
- 原始`product_id`缺失时，继续使用已经冻结的“同一计划 + 文件商品上下文 → 计划商品表现精确唯一匹配”规则。
- 完成该回退后`商品ID`仍为空，则无法确认“计划 × 商品 × 素材”粒度，该行不进入清洗表。

#### Product card

唯一键：

```
计划ID + 商品ID + 素材类型 + 统计开始日期 + 统计结束日期
```

计划ID确实缺失时，对应位置使用计划名称。

其中：

- 输出`Post ID`继续为空。
- `素材类型`必须标准化为来源中的 Product card 类型值。
- 同一计划、同一商品、同一统计区间只保留一个 Product card 事实行。

### 2. 订单经营明细

唯一键：

```
订单ID + SKU ID
```

规则：

- 不把统计开始日期、统计结束日期加入唯一键。
- 同一订单SKU行可能同时出现在月文件和单日文件中，但在清洗累积表中仍属于同一个订单SKU事实。
- 后续再次清洗得到同一`订单ID + SKU ID`时，用新生成完整行替换旧行。
- 如果同一原始文件中已经出现多个相同`订单ID + SKU ID`且内容冲突，属于源事实粒度异常，应在写入前报错。

### 3. 退货退款明细

唯一键：

```
售后单号
```

当前表保存每个售后单的最新清洗状态，不建立售后状态变化历史。

同一售后单号再次出现时：

- 新`采集时间` > 已有`采集时间` → 使用新行整体替换旧行。
- 新`采集时间` < 已有`采集时间` → 跳过该新行并记录“旧快照不覆盖新状态”。
- 新`采集时间` = 已有`采集时间`，且整行内容一致 → 不重复写入。
- 新`采集时间` = 已有`采集时间`，但内容不同 → 报数据冲突，停止该目标表写入。

`采集时间`不加入唯一键。

### 4. 商品评价明细

唯一键：

```
订单ID + 商品ID + SKU ID
```

当前原始评价数据没有独立`评价ID`，因此以订单、商品、SKU共同识别一条评价。

如果后续官方原始数据新增稳定的`评价ID / Review ID`，再优先改用`评价ID`，不在当前版本提前扩展复合键。

### 5. 店铺健康明细 / 履约表现明细

原始表字段保留`采集时间`，Upsert 内部派生：

```
采集日期 = date(采集时间)
```

唯一键分别为：

- 店铺健康明细：`采集日期 + 类别 + 指标`
- 履约表现明细：`采集日期 + 类别 + 指标`

本次清洗结果内部如果同一唯一键出现多条：

- 先按`采集日期 + 类别 + 指标`分组。
- 选择`采集时间`最大的记录作为该组最终候选行。
- 若最大`采集时间`仍对应多条且内容不同 → 报数据冲突。

与现有清洗表相同唯一键比较时：

- 新候选行`采集时间` > 已有行`采集时间` → 替换。
- 新候选行`采集时间` < 已有行`采集时间` → 跳过。
- 采集时间相同且内容一致 → 不重复写入。
- 采集时间相同但内容不同 → 报数据冲突。

不同采集日期继续保留不同历史快照，不新增`采集日期`输出字段。

## 六、安全写入规则

### 1. 原子替换与失败回滚

每张清洗表写入时：

1. 先在目标文件同一目录生成临时 `.xlsx` 文件。
2. 将完整 Upsert 结果写入临时文件。
3. 对临时文件执行表头、行数、唯一键重复等写后校验。
4. 临时文件校验失败时，删除临时文件，原正式文件保持不变，本次 Upsert 失败。
5. 临时文件校验通过后：
   - 如果原正式文件已存在，先保留一份仅用于本次写入回滚的旧文件备份；
   - 如果原正式文件不存在，则直接进入首次创建流程。
6. 使用单次文件替换操作，将临时文件原子替换为正式目标文件。
7. 对替换后的正式目标文件执行最终校验。
8. 最终校验通过：
   - 本次 Upsert 成功；
   - 删除本次旧文件回滚备份。
9. 最终校验失败：
   - 原正式文件此前存在 → 使用旧文件备份恢复正式目标文件；
   - 原正式文件此前不存在 → 删除本次生成的错误正式文件；
   - 本次 Upsert 失败并记录错误。
10. 回滚完成后删除本次临时文件和临时备份文件。

不得直接在正式目标文件上边计算边覆盖写入。最终校验失败时，不得保留已经确认异常的新正式文件。

### 2. 并发约束

当前版本不设计复杂文件锁或多进程锁机制。

执行层必须保证：

```
同一店铺 + 同一目标清洗表
```

同一时间只允许一个清洗任务进入写入阶段。

不同店铺或不同目标清洗表可以独立执行。

## 七、写入前后校验

每张目标表正式写入前必须完成：

1. 本次生成结果的唯一键字段标准化。
2. 检查唯一键必要字段是否为空。
3. 按各表特殊规则处理本次结果内部的重复候选行。
4. 检查剩余结果是否存在重复唯一键。
5. 读取现有清洗表并建立唯一键索引。
6. 对涉及计划的表应用“计划ID优先、计划名称兜底”的最小防重复规则。
7. 对最新状态表执行采集时间比较。
8. 生成完整的新目标表结果。
9. 先写入临时文件并完成临时文件校验。
10. 临时文件校验通过后，如原正式文件存在则创建本次写入的回滚备份。
11. 原子替换正式目标文件。
12. 对替换后的正式目标文件再次执行最终校验，包括表头、行数、文件可正常读取及唯一键不得重复。
13. 最终校验通过 → 删除回滚备份，本次 Upsert 成功。
14. 最终校验失败 → 按“原子替换与失败回滚”规则恢复旧正式文件；首次创建且无旧文件时删除错误新文件，本次 Upsert 失败。

只有最终正式文件通过全部校验，才视为该目标表 Upsert 成功。
