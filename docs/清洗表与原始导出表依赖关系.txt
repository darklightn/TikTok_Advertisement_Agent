# 原始文件选择规则

1. 区间型原始报表只读取与本次清洗 `统计开始日期 + 统计结束日期` 完全匹配的文件，不拼接其他包含、被包含或部分重叠的区间文件。精确区间文件不存在时，按缺少原始数据处理。
2. `GMV Max 计划小时表现`为例外：该源按计划 × 日期逐日文件保存，清洗时读取目标日期范围内已经导出的全部逐日文件并合并。
3. `GMV Max 建议快照`当前只按计划选择最新的 `计划名称__items__采集日期.xlsx`；`summary` 文件继续由导出阶段保存，但当前不参与清洗文件选择、字段生成或缺源判断。
4. 快照型数据继续按各表既定快照规则选择；参考型数据按自身生效规则使用。
5. 清洗阶段只负责完整读取符合上述选择规则的已导出文件，不反查导出阶段理论上是否还应该存在其他计划、商品或日期文件。

# 一、核心诊断表

## 1. 广告户诊断.xlsx

依赖：

```
[区间]
广告户数据/
└─GMV Max 计划总览/

[区间]
计划数据/
└─GMV Max 计划表现/

[快照]
广告户数据/
└─广告账户状态/
```

最终依赖关系：

```
GMV Max 计划总览
+
GMV Max 计划表现
+
广告账户状态
↓
广告户诊断.xlsx
```

`GMV Max 计划总览`负责广告户整体结果；`GMV Max 计划表现`覆盖计划数量、状态及流量表现；`广告账户状态`提供广告户身份信息。实际导出中已经存在计划总览和广告账户状态两类文件。

- `GMV Max 计划商品表现`提供稳定的计划—商品关系及商品信息；当素材原始 `product_id` 缺失时，只允许通过“同一计划 + 素材文件商品上下文”在计划商品表现中做精确唯一匹配，不能模糊猜配。

实际素材表现和素材中心视频是两套独立导出数据。

## 12. 退货退款明细.xlsx

依赖：

```
[快照]
店铺数据/
└─退货退款快照/

[关联历史]
店铺数据/
└─订单明细/
```

最终依赖关系：

```
退货退款快照
+
订单明细历史文件
↓
退货退款明细.xlsx
```

`订单明细`仅用于按订单ID补充订单级字段，例如订单实付金额；退货退款明细不再进行SKU级、商品级归因。

订单历史关联规则：

1. 搜索当前店铺 `店铺数据/订单明细/` 目录下已经存在的全部历史订单文件，不受本次退款快照日期或单一区间文件限制。
2. 只按标准化后的 `Order ID` 匹配。
3. 同一 `Order ID` 出现在多个重叠区间文件时，若所有非空 `Order Amount` 完全一致，视为同一订单并使用该金额。
4. 若同一 `Order ID` 出现多个不同的非空 `Order Amount`，不自行选择，订单实付留空并记录订单金额冲突。
5. 所有历史订单文件均找不到该 `Order ID` 时，订单实付留空，不影响该退款记录其他字段清洗。

# 三、当前不进入任何清洗表的原始导出表

你当前导出能力中，下面 4 类数据暂时不作为固定 16 张清洗表的依赖：

```
店铺数据/
├─商品表现/
├─商品成长机会快照/
├─店铺短视频表现/
└─联盟达人明细/
```

具体处理：

| 原始导出表       | 当前处理                                           |
| ---------------- | -------------------------------------------------- |
| 商品表现         | 当前固定字段已主要由“商品分析表现”提供，不重复接入 |
| 商品成长机会快照 | 16张清洗表没有商品成长机会类字段                   |
| 店铺短视频表现   | 16张清洗表没有自然短视频播放、互动等对应字段       |
| 联盟达人明细     | 16张清洗表没有达人级表现明细字段                   |

这些原始文件继续保留，但清洗 Skill 当前不读取它们。
